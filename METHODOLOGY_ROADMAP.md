# Tenshodo Process — Methodology Roadmap

A pattern or playbook is not complete merely because it sounds convincing.

The methodology is built from observed work, explicit abstraction, evidence, and repeated validation.

## Phase 0 — Consultancy foundation

- [x] M01 — Initialize consultancy methodology repository
  - Define the repository as portable methodology rather than client state.
  - Establish public/confidentiality boundary.
  - Establish pattern maturity model.
  - Seed portable principles, engagement lifecycle, starter playbooks, and templates.
  - Definition of Done: a zero-context consultant can understand the method and its current maturity.

## Phase 1 — Evidence-backed methodology extraction

- [x] M02 — Build pattern evidence matrix and calibrate maturity
  - Extracted sanitized evidence from Tenshodo Exchange flagship durability work.
  - Extracted sanitized evidence from Tenshodo Exchange Management.
  - Recorded the problem, conditions, counterexamples/limits, failure modes, falsifiers, and portability gap for every active pattern.
  - Added artifact-level evidence locators.
  - Reassessed maturity conservatively.
  - Result: PAT-001 through PAT-005 remain Validated; PAT-006 through PAT-011 remain Candidate Pattern; no pattern is Portable.
  - Definition of Done satisfied: every active pattern has explicit evidence and a defensible maturity state.

## Phase 2 — Consultancy engagement kit

- [x] M03 — Build kickoff and discovery kit
  - Adopted governing discovery principle:
    - do not interview for facts the organization can already prove;
    - do not infer facts the organization can cheaply confirm;
    - do not redesign until enough current work and authority are understood.
  - Defined document-led, hybrid, and interview-led discovery modes.
  - Defined evidence escalation ladder and authority exception.
  - Created executive sponsor interview guide.
  - Created evidence/drop-off intake checklist.
  - Created structured current-state discovery assessment.
  - Created field-level Current-State Confidence Map.
  - Created discovery output contract.
  - Standardized sequence: evidence intake → current-process discovery → provisional inference → targeted validation → baseline → transformation.
  - Definition of Done satisfied: consultants can enter a new client without relying on Tenshodo-specific assumptions.

  - Definition of Done: consulting delivery responsibilities are explicit without assuming a client's org structure.

## Phase 3 — Multi-environment validation

- [ ] M06 — Validate on a materially different organization
  - Apply the method outside the original Tenshodo environment.
  - Preserve client confidentiality.
  - Record which patterns survive, fail, or require conditions.

- [ ] M07 — Publish Portable v1
  - Promote only qualifying validated patterns to portable.
  - Create versioned playbook set and client starter pack.
  - Record known non-goals and limitations.

## Continuous work

- Capture new field observations immediately.
- Separate observation from doctrine.
- Prefer a small proven pattern over an elaborate unvalidated framework.
- Deprecate patterns openly when better evidence appears.
