# Tenshodo Process — Methodology Roadmap

A pattern or playbook is not complete merely because it sounds convincing.

The methodology is built from observed work, explicit abstraction, evidence, and repeated validation.

## Phase 0 — Consultancy foundation

- [x] M01 — Initialize consultancy methodology repository
  - Define the repository as portable methodology rather than client state.
  - Establish public/confidentiality boundary.
  - Establish pattern maturity model.
  - Seed portable principles, engagement lifecycle, starter playbooks, and templates.
  - Definition of Done: a zero-context consultant can understand the method and its current maturity.

## Phase 1 — Evidence-backed methodology extraction

- [ ] M02 — Build pattern evidence matrix and calibrate maturity — IN PROGRESS
  - Extract sanitized evidence from Tenshodo Exchange flagship durability work.
  - Extract sanitized evidence from Tenshodo Exchange Management.
  - Record the problem that produced each pattern.
  - Record conditions, counterexamples, failure modes, and unresolved questions.
  - Do not promote a pattern to portable merely because it worked repeatedly inside Tenshodo.
  - Definition of Done: every active pattern has explicit evidence and a defensible maturity state.

## Phase 2 — Consultancy engagement kit

- [ ] M03 — Build kickoff and discovery kit
  - Executive sponsor interview.
  - current-state authority discovery.
  - working-plane inventory.
  - durable-state assessment.
  - process/change pain-point discovery.
  - AI/agent readiness assessment.
  - confidentiality and access boundaries.
  - Definition of Done: consultants can enter a new client without relying on Tenshodo-specific assumptions.

- [ ] M04 — Build client control-plane bootstrap kit
  - starter repository structure;
  - state file;
  - plan;
  - runbook;
  - handoff;
  - decision records;
  - worklogs;
  - authority map;
  - pattern/adoption controls;
  - role-conversation charter template;
  - role-conversation launch-prompt template with stale-state safeguards.
  - Definition of Done: a new client repository and its first governed role conversation can be initialized rapidly and safely.

- [ ] M05 — Define consultancy team operating model
  - engagement lead;
  - operating architect;
  - domain consultants;
  - data/AI architect;
  - technical platform lead;
  - risk/security reviewers;
  - role-conversation stewardship.
  - Definition of Done: consulting delivery responsibilities are explicit without assuming a client's org structure.

## Phase 3 — Multi-environment validation

- [ ] M06 — Validate on a materially different organization
  - Apply the method outside the original Tenshodo environment.
  - Preserve client confidentiality.
  - Record which patterns survive, fail, or require conditions.

- [ ] M07 — Publish Portable v1
  - Promote only qualifying validated patterns to portable.
  - Create versioned playbook set and client starter pack.
  - Record known non-goals and limitations.

## Continuous work

- Capture new field observations immediately.
- Separate observation from doctrine.
- Prefer a small proven pattern over an elaborate unvalidated framework.
- Deprecate patterns openly when better evidence appears.
