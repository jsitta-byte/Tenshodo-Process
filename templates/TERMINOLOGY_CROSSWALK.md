# Terminology Crosswalk

## Purpose

Map semantically similar language across teams, systems, acquisitions, or service models without prematurely renaming either source.

## Rule

**Semantic compatibility comes before label convergence.**

For each pair, determine whether the mapping is exact, partial, broader, narrower, or not equivalent.

| Canonical / proposed shared term | Local/source term | Definition | Object type | Lifecycle/state model | Authoritative source | Key fields | Relationships | Mapping | Decision / notes |
|---|---|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  | exact / partial / broader / narrower / not equivalent |  |

## Integration guidance

Do not rename durable source terminology merely because another team uses a different word.

Use aliases/crosswalks until definitions, object boundaries, lifecycle/state semantics, authority semantics, required fields, and relationships are understood and a deliberate terminology decision is adopted.
