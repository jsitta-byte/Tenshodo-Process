# Discovery Intake Checklist

## Engagement identity

- Client:
- Engagement:
- Executive sponsor:
- Discovery lead:
- Date opened:
- Discovery mode: document-led / hybrid / interview-led / not-yet-classified

## 1. Evidence drop-off

Ask the client to provide or connect what already exists. Do **not** ask them to clean it first.

### People / organization

- [ ] HRIS or workforce export
- [ ] org chart
- [ ] job descriptions
- [ ] contractor roster
- [ ] reporting relationships
- [ ] compensation/job-grade material, if in scope and authorized
- [ ] responsibility or RACI material
- [ ] role/access assignment records

### Process / operating model

- [ ] process library
- [ ] SOPs / work instructions
- [ ] policy library
- [ ] approval matrix
- [ ] recurring operating-calendar / meeting cadence
- [ ] service catalog
- [ ] recurring reports
- [ ] forms / intake mechanisms
- [ ] known exception / escalation procedures

### Systems / data

- [ ] application inventory
- [ ] system owners
- [ ] integrations
- [ ] repositories
- [ ] SharePoint / Drive / document structure
- [ ] ERP / CRM / HRIS / finance systems
- [ ] data warehouse / BI
- [ ] shared spreadsheets / shadow systems
- [ ] identity/access sources

### Strategy / product / customer

- [ ] product/service catalog
- [ ] pricing material
- [ ] customer lifecycle
- [ ] sales process
- [ ] support/onboarding process
- [ ] strategic priorities
- [ ] major transformation initiatives

### AI / automation

- [ ] current AI tools
- [ ] agent workflows
- [ ] prompt libraries
- [ ] RPA / automation inventory
- [ ] AI policies
- [ ] evaluation / approval practices
- [ ] sensitive-data restrictions

### Risk / governance

- [ ] contracts/policies relevant to engagement
- [ ] security requirements
- [ ] privacy/data restrictions
- [ ] records obligations
- [ ] audit findings
- [ ] material risk register, if in scope

## 2. Authority / access boundary

- [ ] executive sponsor identified
- [ ] consulting execution authority documented
- [ ] adoption authority documented
- [ ] prohibited actions documented
- [ ] confidential-data boundary documented
- [ ] systems/connectors approved
- [ ] client control-plane location agreed
- [ ] client data retention/export restrictions documented

## 3. Discovery triage

For each evidence category:

- source exists?
- authoritative?
- current?
- complete enough?
- conflicts?
- follow-up required?

## 4. Discovery-mode decision

### Document-led

Select if authoritative records cover most material current-state facts.

### Hybrid

Select if documentary evidence exists but operating reality requires observation/inference/confirmation.

### Interview-led

Select if little reliable current-state evidence exists.

Record decision:

- Mode:
- Rationale:
- Sponsor acknowledgement:
- Date:

## 5. Immediate red flags

- [ ] multiple editable sources claim authority
- [ ] no reliable workforce membership source
- [ ] unknown decision authority for material operations
- [ ] critical process depends on one person's memory
- [ ] major shadow spreadsheet/manual system
- [ ] ungoverned AI use
- [ ] access/security restriction blocks discovery
- [ ] client expects consultants/AI to self-approve material changes

## 6. Output

At intake completion, create/update:

- evidence/source inventory;
- Current-State Confidence Map;
- sponsor/authority record;
- discovery mode;
- first discovery work queue;
- exact next action.
